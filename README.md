# Attendly — Smart Attendance Using Face Recognition

**Live project webpage (GitHub Pages):** https://sudip09-sys.github.io/Final_Project/ — public overview, interactive sample walkthrough, and documentation. [Webpage source and hosting](docs/Project_Webpage.md).

**Administrator application:** https://attendly-sudip.onrender.com/login — password protected. It currently uses temporary SQLite storage, which resets when Render restarts. Persistent TiDB storage is not yet connected. See [free deployment setup](docs/Free_Deployment.md).

A working Python web application for **supervised, consent-based attendance**. Administrators enroll a roster, open cohort sessions, check in a face or verify attendance manually, and export a CSV. Built by **Sudip Sah**.

## Features

- Password-protected administrator workspace with CSRF protection and a two-hour login session.
- Browser camera capture or JPEG/PNG upload. Exactly one sufficiently large face per image.
- OpenCV decoding, HOG detection and pretrained dlib 128-dimensional face embeddings through `face_recognition`.
- Cohort-scoped nearest-neighbor recognition, distance threshold 0.48 and runner-up margin 0.06.
- Database-enforced unique student ID and unique student/session attendance.
- Encrypted face templates with Fernet. Raw images are processed in memory and never saved by the app.
- Explicit enrollment consent, template withdrawal, student deletion, and an administrator retention command.
- Manual attendance with a required verification note, including for people who decline face enrollment.
- Session closing, roster export including unmarked students, CSV formula escaping, and audit events.
- Responsive dashboard with keyboard-accessible forms and dialogs.

## Quick start

Use Python **3.12**. Linux, macOS or Windows WSL2 is recommended. `dlib` compiles native code and requires a C++ compiler and CMake. Docker is the simplest reproducible install.

```bash
python -m venv .venv
# macOS / Linux / WSL2
source .venv/bin/activate
# Windows PowerShell alternative: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python scripts/setup.py
python scripts/run.py
```

Open **http://127.0.0.1:5000** and use the administrator password you created. This first-run path uses SQLite and needs no database server. No default password or biometric records ship with the project.

## First attendance session

1. Add a student with a student ID, name and cohort, for example `CE 2026`.
2. For optional face enrollment, obtain explicit consent and choose one clear face image. You can also start the check-in camera first and use its current frame in the enrollment dialog.
3. Open **Class sessions**, enter a title and the exact same cohort name, and open the session.
4. Return to **Overview**, select the session, then capture a face or upload an image.
5. Review the result. Duplicate check-ins do not add another record. Unknown or ambiguous faces do not mark attendance.
6. Use **Manual check-in** when needed. Export CSV and close the session when finished.

## MySQL with Docker

After generating `.env`, add random `MYSQL_PASSWORD` and `MYSQL_ROOT_PASSWORD` values. Use URL-safe passwords for this Compose example because they appear in a connection URL. Keep `COOKIE_SECURE=0` only for localhost HTTP.

```bash
docker compose up --build
```

Open **http://127.0.0.1:8000**. MySQL 8.4 stores data in the `mysql-data` volume and is not exposed on the host. Never run `docker compose down -v` unless you intend to remove the database. SQLAlchemy creates the four tables on first startup. See `docs/schema_mysql.sql`.

## Configuration

| Variable | Purpose |
|---|---|
| `SECRET_KEY` | Random Flask signing secret. Keep stable across restarts. |
| `ADMIN_PASSWORD_HASH` | Werkzeug scrypt hash, generated by setup. Never plaintext. |
| `EMBEDDING_KEY` | Fernet key generated by setup. Keep separate from database backups. Losing it makes stored templates unreadable. |
| `DATABASE_URL` | SQLite path locally or `mysql+pymysql://user:password@host:3306/attendance?charset=utf8mb4`. Percent-encode URL password characters outside the Compose example. |
| `DATABASE_TLS` | Set to `1` for an external MySQL-compatible database; verifies its TLS certificate and hostname. |
| `TIMEZONE` | UI and export timezone, defaults to `Asia/Seoul`. Database timestamps are UTC. |
| `COOKIE_SECURE` | `1` for cloud HTTPS. `0` for localhost HTTP only. |
| `FACE_THRESHOLD` | Default `0.48`. Lower is stricter. Validate on consenting participants before changing. |

## Cloud deployment

Use a Docker-capable Python host such as Render, AWS ECS, or Railway. A static Vercel/GitHub Pages deployment cannot run this server and native dlib stack.

1. Publish this folder to a new GitHub repository. Never commit `.env`, local databases, face images, or embeddings.
2. Provision a private MySQL database and configure `DATABASE_URL` using the provider's private hostname. Enable encrypted transport if the database is reached over an untrusted network, using the provider's PyMySQL TLS settings.
3. Deploy this `Dockerfile`, expose `$PORT`, and use `/healthz` for the health check. `render.yaml` and `railway.json` are included.
4. Set `SECRET_KEY`, `ADMIN_PASSWORD_HASH`, `EMBEDDING_KEY`, `COOKIE_SECURE=1`, `TIMEZONE=Asia/Seoul`. Generate secrets locally with setup and enter them in the host's secret settings.
5. Run one application process and one replica. The image-processing lock and login limiter are process-local. Use a shared limiter and a worker queue before scaling out.
6. Verify HTTPS login, a consenting enrollment, check-in, duplicate prevention, manual fallback, export, database persistence after a restart, and template withdrawal.

Deployment is complete only after a successful build, healthy runtime, and verified public HTTPS URL. This package does not claim an unverified live deployment.

## Data lifecycle

Raw uploads and camera frames live only in browser/server memory during processing. Clearing an enrollment form clears its retained frame. Templates persist encrypted until withdrawal, deletion, or explicit retention cleanup. Schedule the following from an environment with the same secrets if you want 90-day cleanup:

```bash
flask --app 'app:create_app()' purge-biometrics --days 90
```

Load your `.env` variables before this Flask CLI command. The cleanup is **not scheduled automatically**. Attendance and audit retention are administrator responsibilities. Backups may retain old templates until backup expiration. Deleting a student cascades to their attendance. Audit entries retain only internal numeric references.

## Practical limits

This is an academic prototype for a small, supervised roster. It has **no liveness or photo/replay attack defense**, no multi-tenant roles, and no automatic absence, grading or employment decisions. A supervisor must review attendance and provide a manual alternative. Recognition can be affected by light, pose, occlusion, age and demographic differences. The library's published benchmark is not this application's measured accuracy.

Cohorts are matched as exact strings. Rosters are not snapshotted at session creation: exports use the current cohort membership, so enroll the roster before running sessions. There is no edit/reenroll screen: withdraw and delete/recreate only when you accept losing linked attendance, otherwise keep manual attendance and extend the schema deliberately. No migration system is included; back up data before schema changes. Embeddings are matched linearly in roster size. `/api/state` loads the small workspace into memory. Add pagination and vector indexing only after measuring growth.
